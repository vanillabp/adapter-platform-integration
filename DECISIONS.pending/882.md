# Two sentences in DECISIONS.md still say version 1 had an outbox

This is not an entry and must not be numbered into `DECISIONS.md`. It is a question for Stephan,
left here because story 882 was told not to touch `DECISIONS.md` while pull request #291 appends
entries to it.

Story 882 removed the claim that a version-1 application kept its two-phase calls in the gruelbox
table `TXNO_OUTBOX`. Stephan's answer on 2026-10-02: there was no outbox in version 1 at all, only
a listener which completed the Camunda 8 job after the commit. Two sentences of `DECISIONS.md`
still rest on the old premise.

The first is in the entry about task wiring:

> Deciding it here would put one engine's notion of a subscription into the core, which is the
> mistake version 1 made with the outbox.

Version 1 made no outbox. What it put into the individual adapters was the eventual-consistency
handling, which is how `migration-adapter/ADAPTER-AUTHORS.md` reads since this story.

The second is in entry 75, about the dispatch lanes:

> Until now every store dispatched on a single thread per node, so an application which completed
> tasks from twenty job executor threads in version 1 handed every completion to one dispatcher.

Read straight, that says version 1 had a dispatcher. What it means is that an application which
completed tasks from twenty threads under version 1 hands every completion to one dispatcher under
version 2, and the sentence can say so.

Where this is referenced: nowhere. Both sentences are prose inside `DECISIONS.md`, and no test,
javadoc or wiki page cites them.
